07PROBLEM

현재 이슈 처리의 구조적 문제

  • 채널 분산
    • 네이버웍스·이메일·슬랙 등 여러 곳으로 이슈 유입
    • 누락 및 중복 접수 발생
  • 이력 소실
    • 처리 내용이 메신저 대화에만 존재
    • 담당자 부재 시 업무 연속성 단절
  • 진행 상태 파악 불가
    • 사업부는 매번 개별 문의 필요
    • 반복 커뮤니케이션 비용 증가
채널 분산 → 이력 소실 → 진행 파악 불가의 악순환
08

AS-IS vs TO-BE

AS-IS (현재)
이슈 접수슬랙·이메일 분산
처리 이력메신저 대화 소실
담당자 배정수동·쏠림
상태 확인개별 문의 필요
비교를 위한 사전 상태 정의
TO-BE (개선)
이슈 접수슬랙 단일 채널
처리 이력Jira 자동 기록
담당자 배정자동 배정
상태 확인실시간 동기화
P0-1 색상 시스템 정상화로 좌/우 구분이 가능
