대화에서 받은 주제를 바탕으로 Confluence Cloud 에디터에 그대로 붙여넣을 수 있는 마크다운 문서를 생성한다. `/ppt`의 문서판 — 슬라이드가 아니라 위키 페이지를 만든다. input 폴더 자료 수집·아카이빙은 하지 않는다.

> Confluence Cloud는 마크다운을 본문에 붙여넣으면 자동으로 네이티브 요소(헤딩·표·코드블록·태스크·리스트)로 변환한다. 이 스킬은 그 변환 규칙에 맞춰 마크다운을 작성한다.

---

## 0. 인자 / 의도 파악

`$ARGUMENTS`에 주제가 들어왔으면 그것을 출발점으로 삼는다. 비어있으면 사용자에게 한 번만 다음을 묻는다 (AskUserQuestion):

1. 주제 / 핵심 메시지
2. 문서 유형 (template) — `report | proposal | meeting | retro | rfc | guide` 중 선택
3. 작성자·독자 (사내 팀 / 사외 / 임원 보고 등)

이미 충분한 맥락이 대화에 있으면 묻지 말고 바로 진행.

선택 정보 (인자에 적혀있으면 추출):
- `title:` — 페이지 제목
- `subtitle:` — 부제 / 한 줄 요약
- `author:` — 작성자 (인자·맥락에 없으면 0단계에서 사용자에게 묻는다. 임의의 기본값을 채우지 않는다)
- `space:` — Confluence Space (예: ENG, PRD)
- `template:` — 문서 유형
- `output:` — 출력 디렉토리명 (기본: `output/YYYY-MM-DD_제목`)

## 1. 출력 경로 결정

오늘 날짜와 title 조합:
- 형식: `output/YYYY-MM-DD_제목`
- title의 파일명 불가 문자(`/ \ : * ? " < > |`) 제거, 공백은 `_`로 대체
- 예: `output/2026-05-08_5월_KPI_리뷰`

이후 단계에서 `{OUT}` 은 이 경로를 가리킨다.

## 2. 콘텐츠 분석 (대화 맥락만 사용)

input 폴더는 읽지 않는다. 대화 맥락 + 사용자 인자만 사용.

도출:

1. **핵심 메시지(TL;DR)** — 한 문장 결론
2. **타겟 독자** — 누가 읽고, 무엇을 결정/실행해야 하는지
3. **데이터/숫자** — 표 또는 인라인 메트릭으로 부각
4. **결정/액션** — 독자가 취해야 할 행동, 의사결정 사안
5. **참고 링크** — 관련 페이지·티켓·외부 자료 (URL이 있는 경우만)

## 3. 문서 구조 설계

`template`별 권장 흐름:

| template | 권장 흐름 |
|---|---|
| `report` | 메타 → TL;DR → 배경 → 데이터·분석 → 결론 → 다음 단계 |
| `proposal` | 메타 → TL;DR → 문제 정의 → 현황 → 제안(옵션 비교 표) → 기대효과 → 일정·비용 → 의사결정 요청 |
| `meeting` | 메타(일시/참석자) → 안건 → 논의 요약 → 결정 사항 → 액션 아이템(담당/기한) → 다음 회의 |
| `retro` | 메타 → 회고 정보 → 잘된 점 → 아쉬운 점 → 액션 아이템 → 다음 회고까지의 약속 |
| `rfc` | 메타 → 요약 → 배경 → 문제 → 고려한 옵션 → 결정 → 영향·리스크 → 마이그레이션 → 미해결 질문 |
| `guide` | 메타 → 개요 → 사전 준비 → 단계별 절차 → 트러블슈팅 → FAQ → 참고 자료 |

### 작성 원칙

- **첫 화면 = 의사결정 가능**. 메타 표 + TL;DR을 위에 배치
- **한 단락 = 한 메시지**. 3~4문장 이내
- 데이터는 표, 흐름은 리스트, 비교는 두 컬럼 표
- 외부 링크는 본문에 자연스럽게, 참고 자료는 문서 끝 섹션에 모음
- 코드 블록은 언어 지정 (` ```python `, ` ```bash `)
- 한국어 본문은 단어 사이 공백 유지(가독성·줄바꿈)

## 4. Confluence 마크다운 작성 규칙

### A. 자동 변환되는 요소 (그대로 작성)

| 마크다운 | Confluence 결과 |
|---|---|
| `# H1` ~ `###### H6` | 헤딩 (H1은 페이지 제목과 별개) |
| `**굵게**` `*기울임*` `~~취소~~` `\`코드\`` | 텍스트 포맷 |
| `- 항목` / `1. 항목` | 불릿·번호 리스트 (들여쓰기 2칸 = 중첩) |
| `- [ ]` / `- [x]` | Confluence 태스크 |
| GFM 표 (`\| h \|`) | 표 |
| ` ```언어 ` 코드 펜스 | 코드 블록 + 신택스 하이라이트 |
| `> 인용` | 인용 블록 |
| `[텍스트](URL)` | 링크 |
| `![alt](파일.png)` | 이미지 (붙여넣은 후 첨부 파일 교체 필요) |
| `---` | 수평선 |

### B. 1:1 대응이 없는 요소 — 컨벤션 + 수동 변환 안내

문서 끝의 "수동 변환 안내" 섹션에 정리해 둔다.

| 의도 | 본문 표기 | 붙여넣은 후 변환 |
|---|---|---|
| Info 패널 | `> ℹ️ **참고:** 내용` | `/info` 패널로 |
| Warning 패널 | `> ⚠️ **주의:** 내용` | `/warning` 패널로 |
| Note 패널 | `> 📝 **노트:** 내용` | `/note` 패널로 |
| Success 패널 | `> ✅ **완료:** 내용` | `/success` 패널로 |
| 상태 라벨 | `**[STATUS: GREEN]**` (RED/YELLOW/GREEN/DRAFT/IN PROGRESS) | `/status` 라벨로 |
| 사용자 멘션 | `@홍길동` | 붙여넣은 후 `@`로 재입력 |
| 페이지 링크 | `[페이지명](URL 또는 TBD)` | 필요 시 Confluence 내부 링크로 |
| 익스팬드(접기) | `<details><summary>제목</summary>\n내용\n</details>` | 일부 환경 자동, 안 되면 `/expand` |

### C. 메타 헤더 (Page Properties)

문서 최상단에 항상 메타 표를 둔다. 붙여넣은 후 `/page properties` 매크로로 감싸면 Page Properties Report에서 자동 집계된다.

```markdown
| 항목 | 값 |
|---|---|
| 작성자 | @{author} |
| 작성일 | {YYYY-MM-DD} |
| 분류 | {template} |
| 상태 | **[STATUS: DRAFT]** |
| 관련 링크 | [티켓](URL) |
```

### D. TL;DR 패턴 (모든 template 공통, 메타 바로 다음)

```markdown
## TL;DR

> 💡 **요약:** 한 문장 핵심 메시지

- 핵심 포인트 1
- 핵심 포인트 2
- 핵심 포인트 3
```

### E. 액션 아이템 패턴 (`meeting` / `retro` / `proposal` 필수)

표 또는 태스크 리스트 둘 다 OK. 표 형식이 Page Properties Report와 결합하기 좋다.

```markdown
## 액션 아이템

| 작업 | 담당 | 기한 | 상태 |
|---|---|---|---|
| API 스펙 확정 | @홍길동 | 2026-05-15 | **[STATUS: IN PROGRESS]** |
| 인프라 견적 | @김철수 | 2026-05-20 | **[STATUS: TO DO]** |
```

또는:

```markdown
- [ ] @홍길동 — API 스펙 확정 (2026-05-15)
- [ ] @김철수 — 인프라 견적 (2026-05-20)
```

### F. 옵션 비교 패턴 (`proposal` / `rfc` 권장)

```markdown
## 옵션 비교

| 옵션 | 장점 | 단점 | 비용 | 추천 |
|---|---|---|---|---|
| A. 내부 구축 | 통제권 ↑, 커스텀 자유 | 인력 6MM | 1.2억 | △ |
| B. SaaS 도입 | 빠른 적용, 운영 위탁 | 라이선스 종속 | 월 350만 | ○ |
| C. 하이브리드 | 단계 도입 가능 | 복잡도 ↑ | 8천만 + 월 120만 | ◎ |
```

## 5. 문서 작성

`{OUT}/confluence.md` 에 작성한다. 디렉토리가 없으면 만든다.

문서 골격 (template과 무관하게 공통 뼈대):

```markdown
# {페이지 제목}

| 항목 | 값 |
|---|---|
| 작성자 | @{author} |
| 작성일 | {YYYY-MM-DD} |
| 분류 | {template} |
| 상태 | **[STATUS: DRAFT]** |

---

## TL;DR

> 💡 **요약:** {한 문장 결론}

- {핵심 1}
- {핵심 2}
- {핵심 3}

---

## {본문 섹션 1}

...

## {본문 섹션 2}

...

---

## 액션 아이템 / 다음 단계

- [ ] @{담당자} — {작업} ({YYYY-MM-DD})

---

## 참고 자료

- [관련 페이지](URL)
- [티켓](URL)

---

> 📋 **수동 변환 안내** (Confluence에 붙여넣은 후)
>
> 1. 메타 표 위에서 `/page properties` 매크로 적용
> 2. `> ℹ️/⚠️/📝/✅` 인용 블록 → `/info` `/warning` `/note` `/success` 패널
> 3. `**[STATUS: ...]**` → `/status` 라벨 (색상: GREEN·YELLOW·RED·BLUE·GREY)
> 4. `@이름` → `@`로 재입력해 사용자 멘션
> 5. 이미지(`![](파일.png)`) → 첨부 후 드래그앤드롭 또는 `/image`
> 6. 필요 시 `/toc` 매크로를 TL;DR 위에 삽입
```

## 6. 완료 보고

```
✓ Confluence 문서: {OUT}/confluence.md

총 N개 섹션:
  - 메타 헤더
  - TL;DR
  - {본문 섹션들}
  - 액션 아이템
  - 참고 자료

붙여넣기 절차:
  1. Confluence 페이지 편집 모드 → 본문 클릭
  2. {OUT}/confluence.md 내용 전체 복사 → 붙여넣기
     (Cloud 에디터가 마크다운을 자동 변환)
  3. 메타 표 위에서 /page properties 적용
  4. 인용(>)으로 표시한 ℹ️/⚠️/📝/✅ 블록을 /info /warning /note /success 패널로 교체
  5. **[STATUS: ...]**를 /status 라벨로 교체
  6. @이름을 @로 다시 입력해 멘션으로 변환
  7. 이미지가 있으면 첨부파일 업로드 후 교체

열기: open "{OUT}/confluence.md"
```

## 다른 스킬과의 차이

- 이 스킬(`/confluence`)은 **대화 맥락만**으로 가볍게 위키 문서 1장 생성
- 슬라이드(HTML PT)가 필요하면 `/ppt`
- input 폴더에 자료가 있고 슬라이드 + Confluence 동시 생성이 필요하면 `/doc-gen` (request.yaml의 `confluence: true`)
