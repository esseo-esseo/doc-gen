# Architecture Decision Records

## 철학
가독성과 이식성 최우선. 외부 의존성 없는 단일 HTML 파일 생성. Claude의 언어·시각 이해 능력으로 콘텐츠를 구조화하고, 순수 Python 표준 라이브러리로 렌더링한다.

---

### ADR-001: 출력 형식을 PPT 대신 HTML로 선택
**결정**: python-pptx 대신 순수 HTML/CSS/JS로 슬라이드 프레젠테이션을 생성한다.
**이유**: 브라우저만 있으면 바로 열 수 있고, PDF 저장·공유·버전 관리가 쉽다. 외부 라이브러리 설치가 불필요하다.
**트레이드오프**: PowerPoint 파일 형식으로 직접 편집할 수 없다. (HTML 소스 수정으로 대체)

### ADR-002: 이미지를 base64로 인라인 임베딩
**결정**: 슬라이드에 포함된 이미지를 base64 data URL로 HTML에 직접 임베딩한다.
**이유**: 단일 HTML 파일로 완결성을 유지해, 파일 이동 시 이미지 링크가 깨지지 않는다.
**트레이드오프**: 이미지가 많으면 HTML 파일 크기가 커진다. 현재 사용 패턴(발표 자료)에서는 허용 범위.

### ADR-003: PDF 다운로드를 브라우저 인쇄로 구현
**결정**: PDF 저장 버튼 클릭 시 `window.print()`를 호출한다. `@media print` CSS로 각 슬라이드를 별도 페이지로 출력한다.
**이유**: 서버리스, CDN 없음, 오프라인 동작. html2canvas/jsPDF보다 렌더링 품질이 높다.
**트레이드오프**: 브라우저 인쇄 다이얼로그를 거쳐야 한다. (직접 파일 저장 아님)

### ADR-004: 구조-렌더링 분리 (slides.json → index.html)
**결정**: Claude가 slides.json을 생성하고 render_html.py가 HTML로 변환한다.
**이유**: 콘텐츠 구조화와 디자인 렌더링을 독립적으로 개선할 수 있다. slides.json을 직접 수정해 재렌더링이 가능하다.
**트레이드오프**: 중간 파일(slides.json)이 생기지만 디버깅 및 재사용이 쉬워진다.

### ADR-005: Confluence 직접 API 연동 미적용
**결정**: Confluence 출력은 `confluence-ready.md`를 생성하고 사용자가 직접 붙여넣는다.
**이유**: Atlassian API 인증 설정 없이 즉시 사용 가능. 불필요한 복잡성 배제.
**트레이드오프**: 수동 붙여넣기 단계 필요. 추후 API 연동으로 업그레이드 가능.
